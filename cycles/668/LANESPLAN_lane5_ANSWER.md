TITLE: Give each live Peddler Pins visit a distinct transaction identity
MILESTONE: S6 — Stitched one-purpose map stops, Peddler pocket-item purchase
LANE: lane5

## Goal
Stop an obsolete Pins purchase/Leave request from a previous Peddler opening authorizing a second, otherwise identical opening. This preserves an already-routed useful stop, rather than adding unwired shop data, more service forecasts, new buttons or new corridor UI. Small one-service/one-service-test change; keep the existing routed test as a regression.

## Actual code and rule
`scripts/run_stitched_peddler_pins.gd` admits one Stitched Peddler visit at a nonempty trimmed node ID, with exactly four distinct non-LOST/LOST-capable doll records ranked 1–4, an exact four-doll Walk pocket dictionary (maximum two legal pocket items per doll), a nonnegative gold wallet and a caller-provided positive integer price. Its `buy_pins(hero_id, expected_node_id, expected_snapshot)` appends one literal `"pins"` to an eligible non-LOST doll's free pocket, deducts the supplied price exactly once and consumes the visit. `leave(expected_node_id, expected_snapshot)` is free and consumes the visit. The purchase does not use the pins during the Walk, and draws no RNG. The legal pocket IDs currently are `thimble_tonic`, `fresh_stuffing`, `starch`, `dye`, `pins` and `spare_spool`. Existing service tests use `NODE = "route-peddler-9"`, `PRICE = 35`; the genuine routed test has its own run-authored 10-gold pins sale. Do NOT standardize or change either price.

Concrete defect: `_matches_open` checks node plus full `read_state()`, but `read_state()` has no identity unique to an opening. Two visits opened at the same node with the same four dolls, pockets, wallet and quote produce identical OPEN snapshots. A saved Pins callback from visit A can therefore purchase or Leave on newly opened visit B. The closely related, existing `scripts/run_stitched_peddler_fresh_stuffing.gd` has a process-local monotonic `_next_serial` and `visit_id` inside `read_state()`, which the existing exact-state guard already authenticates.

## Implementation
Add a nonempty, unique process-local `visit_id` on successful Pins admission (monotonic counter, not clock, random draw or hash of wallet/party); expose it from valid `read_state()` and expose an empty unusable one on invalid state. Do not add a field to the existing 10-key `quote()`, change UI, receipt schema, prices, effects, pocket limit or public method signatures. Because the existing guard compares complete state, old or forged visit IDs then fail for both Buy and Leave. Preserve deep detachment, once-only status changes, legal duplicate pins in a not-full pocket, free Leave and all negative gates.

## Acceptance criteria
AC1: Two successful independent Pins admissions with identical `NODE`, four ranked dolls, pocket ledger, wallet and 35-gold caller quote yield distinct nonempty `read_state().visit_id`, while every existing quote choice/economic value, initial eligibility and RNG state stays unchanged. Invalid admission remains inert and exposes no usable ID. Prove with `tests/run_stitched_peddler_pins_test.gd`.
AC2: Given visit A's genuine OPEN snapshot, a newly opened identical visit B rejects both `buy_pins("warden", NODE, A_snapshot)` and `leave(NODE, A_snapshot)` before and after A is consumed, without spending B's gold, appending pins or consuming B. Missing/altered `visit_id` is equally refused; B's own current snapshot works. Prove with deterministic dual-visit tests.
AC3: Authentic B can still buy exactly one `"pins"` for a non-LOST doll with a 0-or-1-item pocket, paying precisely the caller's positive integer quote once; a second copy is permitted if there was one slot. Full-pocket, LOST-target, poor-wallet, wrong-node, malformed, stale and replay requests remain harmless; free Leave remains possible, and neither path uses or activates pins or RNG. Preserve the existing service test's negative coverage.
AC4: `tests/stitched_s6_routed_pins_live_test.gd` continues to pass: a generated live Peddler/Shop, its genuine 10-gold Pins button, wallet and two-slot pocket, consumed visit and routed Save/Continue behavior are unchanged. No new live wiring, app/session/save change or extra screen.

## Tests and boundaries
Extend `tests/run_stitched_peddler_pins_test.gd` with `_test_reopened_visit_identity()`, called from `_initialize()`, using its existing `_party()`, `_pockets()`, `NODE`, `PRICE` and helper. Assert A/B economic states match after removing ONLY visit_id; returned IDs are immutable by mutations to detached dictionaries; the ordinary legal path still buys/Leaves. Keep all existing admission, quote, invalid target, stale state and idempotence checks. Run Godot 4.7.2 headlessly: `godot --headless --path . --script res://tests/run_stitched_peddler_pins_test.gd`, then `godot --headless --path . --script res://tests/stitched_s6_routed_pins_live_test.gd` (or the repo's equivalent allowed Godot runner). Update the routed test only for a demonstrated assertion of the former state shape; retain its genuine run and negative witnesses.

The coder has standing authority for the smallest necessary supporting code and affected existing-test corrections, including a shared test if demonstrably required by THIS unchanged goal, but must preserve negative/fail-closed coverage. Never expand this into an app/session callback rewrite, broader Peddler save-generation work, service quote/forecast, new merchandise, visual control, price change or balance pass. No edits to `scripts/app.gd`, `scripts/stitched/stitched_run_session.gd`, S14/S15 combat/save, current lane5 Patch Stall catalog/stock tests, other lanes' enemy/Event files, or any owner-owned corridor/junction/visit/fight screen. The next main cycle owns mounted Peddler Save callback generation, not this Pins service. This is the existing Pins purchase identity alone.

TITLE: Reject prior-visit Pins purchases at a reopened Peddler
MILESTONE: S6 — Stitched Peddler split-stop Pins transaction

## Goal
Fix a real Pins stop transaction bug: two independently opened Peddler Pins visits at one node with identical economic state currently accept one another's OPEN snapshots. An old button callback or saved intent can wrongly charge a newly opened stop or prematurely Leave it. Give every valid Pins visit a distinct non-replayable identity; do not change the Pins item, price or stop UI.

## Details (all rules/numbers/names needed, copied from the docs)
Design v4 Stitched has four ranked dolls (ranks 1, 2, 3, 4). The Peddler is a single-purpose in-corridor service; owner owns its screen and choice layout. `RunStitchedPeddlerPins.open_stitched(node_id, heroes, pockets, gold, quoted_price)` is already called through the genuine routed Pins stop (`tests/stitched_s6_routed_pins_live_test.gd`). It requires a nonempty trimmed route node ID; exactly four hero Dictionaries with distinct nonempty IDs, distinct int ranks 1..4 and boolean `lost`; exactly the same four keys in a pocket Dictionary; each pocket is an Array of 0..2 strings from `["thimble_tonic","fresh_stuffing","starch","dye","pins","spare_spool"]`; nonnegative integer gold; and a positive integer externally supplied `quoted_price`. Invalid visits do nothing. `read_state()` is detached, holding node, status, mode `"stitched"`, gold, quote, heroes, pockets, eligibility and consumed flag. `quote()` currently has 10 keys, `"buy_pins"` when one non-LOST doll has pocket room and the wallet pays, plus free `"leave"` whenever open.

`buy_pins(hero_id, expected_node_id, expected_snapshot)` may be called only with a current full-state snapshot and same node. It appends EXACTLY ONE literal `"pins"` to ONLY that hero's pocket, charges exactly the caller quote, and moves from `"open"` to `"used"`. The same item can occupy both slots if the chosen doll already had one. It never uses the Pins' later Walk action, changes HP/FRAY/candle/ranks, creates a new item effect or consumes RNG. `leave(expected_node_id, expected_snapshot)` moves from open to left at no charge. A consumed or invalid visit cannot be used again. The existing service-test fixture `tests/run_stitched_peddler_pins_test.gd` uses `NODE = "route-peddler-9"`, `PRICE = 35`; the routed game test uses an independently authored 10-gold sale. Both prices are unchanged.

CURRENT BUG IN SOURCE: `scripts/run_stitched_peddler_pins.gd::_matches_open` compares `expected_snapshot == read_state()`, but `read_state()` lacks `visit_id`. Two valid visits opened at the same NODE with same roster, pockets, gold and quote are indistinguishable. Follow the already-existing, unreserved pattern in `scripts/run_stitched_peddler_fresh_stuffing.gd`: a static monotonic `_next_serial` and instance `_visit_id`, generated once ONLY after successful admission. Publish a nonempty visit ID in valid `read_state()`, and `visit_id: ""` in invalid state. Existing exact-state comparison will then reject a foreign, missing or forged visit ID, even when all other fields match. Use no clock, randomness, price-derived ID or new external caller argument. Keep `quote()` unchanged, including its 10 keys and no new forecasts; preserve all existing transaction receipt keys and detached snapshots. No new button, new screen, UI or art.

## Files likely touched

- `tests/run_stitched_peddler_pins_test.gd`: extend existing headless test (no new file) with dual-visit same-ledger replay and forged-ID cases, plus existing invariant checks.
- `tests/stitched_s6_routed_pins_live_test.gd`: a **regression run**; edit only if an actual old exact read_state shape assertion needs the smallest correction, keeping its real route, buttons, wallet, save and negative coverage intact.
