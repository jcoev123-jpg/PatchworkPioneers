# Lessons for coding agents (auto-collected by the relay)

## Always

- Before finishing, compare your actual diff against every acceptance criterion and make sure each new behavior has an executable test; a green pre-existing suite can hide a missing feature.
- Run the relay's required full suite in the foreground on the final, unchanged worktree and wait for its real result; a background or abandoned run proves nothing.
- If the full suite fails, compare each failure with the same revision on the main branch before calling it pre-existing, and repair any new failure without weakening required coverage.
- Keep seed searches, probe tests and ad-hoc runners outside the game worktree; check `git status` before the final suite and remove stray debug tests, their `.gd.uid` files and scratch files.
- In a fresh Godot worktree, run the headless `--import` step before any `-s` test; a missing `.godot/global_script_class_cache.cfg` gives misleading `class_name` parse errors that are not code bugs.
- When you change something shared (a test helper's parameters, a focus order, a seeded pool, a fixed control pool), search every test and override that depends on it and update them too, not just the feature's own test.

## Recent

- For catalog-only additions already handled by shipped routing and settlement services, keep changes to the catalog and an independent contract test rather than opportunistically editing shared live-route regressions; competing updates to those tests can break resource invariants and conflict with concurrent master work. If integration-test reconciliation is truly necessary, preserve current mainline helper semantics and both branches' coverage, then run the full suite on the integrated tree. (lane8 DeepSeek web)
- Treat the relay suite as incremental: it may reuse prior passes on an unchanged worktree, or run changed-file-related tests first and skip the rest if those fail. Check the final summary for unrun tests rather than interpreting a partial pass count as a full-suite pass. (lane8 ChatGPT repair)
- Do not infer that a free or Leave action is RNG-neutral; a mounted visit can advance the run RNG even without a wallet cost. Verify actual RNG state around the live route before using such an action as a no-draw control. (lane8 ChatGPT repair)
- The live roadside selector sorts its eligible Event IDs and uses one `randi_range` draw, so even append-only catalog growth changes which Event an old map/toll seed reaches. Re-derive rare witness seeds through the real map → toll → rotation pipeline, and verify specialized mounted routes that inherit the shared fixture discovery; a bounded fallback search may not find them. (lane8 ChatGPT repair)
- In tests of weighted or otherwise variable action schedules, identify the required behavior from the emitted action data rather than assuming it occurs on a particular turn or is the first action. Preserve checks of the actual outcomes once that action is observed. (lane5 Claude/Mistral web)
- When adapting live regression tests for multiple action variants, keep non-vacuous witness counts and variant-specific assertions for every required path; an early `continue` can turn a failing path into silently missing coverage. Reconcile supporting test edits with the latest mainline assertions before treating an isolated green suite as merge-safe. (lane4 ChatGPT repair)
- Treat relay report markers as a machine-readable interface: place a nonempty, strict JSON object with straight double quotes between `@@CODER_STATUS_START@@` and `@@CODER_STATUS_END@@`, and validate the acceptance-check JSON too. Verify that the submitted report actually contains those parseable blocks at the required delivery location; passing tests cannot compensate for malformed or missing status data. (lane5 Claude/Mistral web)
- In mounted Godot UI, let child controls inherit the application's root Theme rather than assigning the same Theme locally in `_ready()`; an explicit child Theme can break shell-wide inheritance contracts even when focused feature and theme-toggle tests pass. (lane6 ChatGPT Chat mode)
- In mounted Godot route tests, distinguish a retained UI node from an active service: non-service transitions can hide a panel without freeing it, so assert visibility/activation and unchanged gameplay effects instead of requiring the node to be null. (lane8 ChatGPT repair)
- Before handing off a coding lane, inspect both `git log master..HEAD` and `git diff --name-status master..HEAD` against current master; inherited side-branch commits can silently include unrelated gameplay and test changes even when the working tree is clean. Keep the submitted branch limited to the lane's authorized feature and necessary supporting changes. (lane4 gemini-3.8-flash-high)
